# CarGPS v1.1.2

本版本优先处理已在现场发生的 GPS 丢失、补传阻塞和错误定位锚点问题。

- 待上传 GPS 从整文件 JSON 改为 SQLite 可靠队列，避免 JSON 损坏导致整批缓存丢失。
- 每个点先落盘再上传；仅服务端 `code=0` 后删除，断网、失败和重启均保留。
- 单线程按 `position_time` 顺序补传，失败指数退避，网络恢复后自动继续。
- 退避期间新增GPS只写入SQLite，不再每秒重复发起失败请求；到期或网络恢复后再补传。
- 自动迁移 v1.1.1 的 `pending_gps.json`；无法解析的旧文件改名保留，不静默删除。
- 冷启动及超过 5 分钟断档后采用连续两点确认，避免一次错误首点成为过滤锚点。
- 日志文件写入改为后台串行，维护频率由每 10 条降为每 500 条，避免阻塞定位回调。
- GPS 诊断弹窗只显示速度，不再调用速度接口，并限制列表为最近 100 点。
- 上传增加 `accuracy`、`location_type`、`satellites` 字段，为后端统一过滤预留数据。
- 服务销毁时停止定位、取消请求、清理回调并关闭队列。

仍需后端配合的事项：补传速度不作为实时速度展示、数据库幂等唯一约束、按接收时间与原始定位时间区分补传，以及里程过滤规则统一。
